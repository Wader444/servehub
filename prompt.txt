# MASTER PROMPT — COMMUNITY SERVICE MANAGEMENT PORTAL

## ROLE

Act as a Senior Full-Stack Developer and Software Architect helping a 3rd-year IT student build a practical, polished academic project under a strict deadline.

The goal is NOT to build an enterprise application.

The goal is to build a project that is:

* Simple enough to complete within a short deadline
* Easy to understand and explain in a viva
* Professionally designed
* Properly structured
* More impressive than a basic CRUD project
* Easy to run locally
* Easy to deploy

The project is:

# COMMUNITY SERVICE MANAGEMENT PORTAL

A web application where users can discover community services and events, request services, volunteer for activities, and track their participation.

---

# DEVELOPER BACKGROUND

The developer:

* Is a 3rd-year IT student.
* Has strong MySQL knowledge.
* Understands HTML, CSS and JavaScript.
* Is learning full-stack development.
* Has limited time before project submission.

Therefore:

DO NOT over-engineer.

DO NOT use microservices.

DO NOT use unnecessary AI.

Prefer simple, understandable implementations.

# MODULE 3 — SERVICE REQUESTS

A user can request a service.

Request statuses:

PENDING
↓
APPROVED
↓
COMPLETED

Alternative:

PENDING → REJECTED

Admin can update the status.

Users can see their request history.

Display status using badges.

Example:

PENDING   → Yellow
APPROVED  → Blue
COMPLETED → Green
REJECTED  → Red

* Browse opportunities

Admin can:

* Approve application

# MODULE 5 — VOLUNTEER HOURS

# ONE STANDOUT FEATURE

## COMMUNITY IMPACT SCORE

For volunteers:

Impact Score =
completed activities × 10
+
volunteer hours × 2

Completed Activities = 5
Volunteer Hours = 12

5 × 10 + 12 × 2 = 74

Display:

# DATABASE RULES

Use:

* Primary keys
* Foreign keys
* Unique constraints
* NOT NULL
* timestamps
* indexes where useful

Use transactions for event registration.

For event registration:

1. Check event exists.
2. Check capacity.
3. Check duplicate registration.
4. Insert registration.
5. Update available slots.
6. Commit.

Rollback if something fails.

Before coding, produce:

1. Architecture

3. Database schema
4. API list

6. Development phases

1. Explain what will be built.
2. Create the required files.
3. Implement the feature.
4. Run/test it.
5. Fix errors.
6. Only then proceed to the next phase.
